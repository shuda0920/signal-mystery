# 遊戲式學習設計與製作

根據使用者的目標與現有專案，設計並實作能讓玩家透過行動、決策、結果與修正來學習的遊戲。沿用專案既有技術、規範和使用者指定的語言與平台；不要預設所有作品都必須是課堂遊戲。資訊不足時先檢查專案與現有素材，必要時詢問最影響設計的問題；可合理推定之處標示假設並繼續。

## 設計與製作

1. 確認學習者、先備能力、情境、設備、時間與限制。把目標寫成可觀察的行動、條件與判斷標準，例如「依三回合資料比較方案並解釋取捨」，而非只有「了解主題」。依事實、程序、概念或策略能力選擇適合的活動。
2. 建立簡短的目標對照：每個重要目標對應玩家行動、所需資訊、結果或回饋，以及可觀察的學習證據。讓推進遊戲需要運用目標能力；檢查是否能靠猜測、固定按鈕順序或與目標無關的獎勵通關。必要時調整規則或情境。
3. 設計核心循環：觀察資訊 → 預測或選擇 → 依明確規則產生狀態變化 → 查看結果與原因 → 調整並再試。定義狀態、行動、限制、目標、結算順序與勝敗條件；提供有意義的選擇及可理解的代價與後果。玩法由學習行動決定，可採分支情境、模擬、策略或其他合適形式，不強制使用題目或特定類型。
4. 將挑戰由簡至複，逐步增加需要考慮的關係。依困難提供提示、示範或資訊標記，並在適當時減少支援。讓失敗可回看、比較並重試；回饋解釋行動與結果的關係，依任務決定是否立即揭曉答案。區分回饋、獎勵與評量，避免分數誘導偏離目標。
5. 呈現可讀的資料、單位、時間與規則，避免只靠顏色傳達重要資訊；依平台支援鍵盤、字幕、字級、音量與可調節奏等適用的無障礙方式。控制文字、動畫和操作負荷。簡化模型時說明其假設，不把模型結果當成真實世界必然結果。
6. 先做足以回答關鍵設計問題的可玩原型，接著依請求與專案範圍完成實作。試玩或測試規則、狀態轉換、回饋、重試與主要操作；觀察玩家是否使用目標知識、理解資料並能說明理由。高分或完成回合不等於理解。根據觀察修正；若無法取得真實學習者試玩，明確標示尚未驗證，不捏造結果。
7. 依情境安排遊玩前的先備知識、遊玩中的引導，以及遊玩後的反思或新情境應用。評估分開考慮參與、當下學習、延後保留和遷移；依目標採用解釋、操作或新情境任務，並記錄提供的提示。不要僅憑分數、點擊或遊玩時間宣稱學習成效，也不要把相關性當因果。

## 交付時

說明學習者與目標、核心循環、目標與行動及證據的對應、如何執行或遊玩、已完成的驗證、假設與尚待試玩的限制。依使用者要求調整詳略，不要把內部設計說明強塞進玩家介面。若只要求構想或修改，不要擅自擴展成完整產品。
